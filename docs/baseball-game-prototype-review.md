# 야구 게임 프로토타입 자체 플레이 리뷰

## 점검 범위

- 데스크톱과 390px 모바일 화면에서 첫 진입 상태 확인
- 볼·스트라이크·파울·볼넷·컨택·안타·홈런 흐름 직접 진행
- 3아웃 공수교대와 3이닝 경기 종료까지 브라우저 자동 플레이
- 점수, 주자, 이닝, 공수, 다음 주사위가 판정 직후 함께 갱신되는지 확인

## 발견한 부족점과 반영한 피드백

| 부족점                                      | 플레이 중 혼란                                            | 반영한 개선                                                                                  |
| ------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 기존 상태판이 디버그 패널처럼 보임          | 현재 공격팀과 경기 상황을 한눈에 파악하기 어려움          | 상단 방송형 스코어버그, 현재 타석 카드, 실제 야구장 방향의 다이아몬드, 판정 하단 자막을 구성 |
| B/S/O만 표시                                | 야구에 익숙하지 않은 사용자는 약어를 바로 이해하기 어려움 | 현재 타석 카드에 `볼 n`, `스트라이크 n`, `n사`, 주자 상황을 한글로 함께 표시                 |
| 모바일에서 굴리기까지 스크롤 필요           | 상황을 확인한 뒤 조작부를 찾느라 흐름이 끊김              | 현재 필요한 D12 굴리기 버튼을 화면 하단에 고정하고 단계·공격/수비 주체를 함께 표시           |
| 랜덤 굴리기 버튼이 두 위치에 중복           | 어느 버튼이 주 조작인지 불명확함                          | 고정 버튼 하나로 통합하고 하단 패널은 강제 면 입력용 디버그 도구로 분리                      |
| 모든 세 번째 아웃에 “진루와 득점 취소” 노출 | 삼진처럼 취소할 진루가 없는 상황도 복잡하게 보임          | 실제 주자 진루 또는 득점이 취소될 때만 해당 문구를 추가                                      |
| 카운트 진행 뒤 “다음 타자”로 안내           | 볼·스트라이크·파울 뒤 타자가 바뀐 것으로 오해할 수 있음   | 같은 타석, 새 타자, 공수교대 첫 타자를 구분한 `NEXT` 안내 추가                               |
| 득점 변화의 시각적 반응이 약함              | 결과 자막과 점수판의 연결이 덜 즉각적임                   | 득점 숫자 팝 애니메이션과 득점·아웃·공수교대 색상 강조 추가                                  |

## 검증 기준

- 같은 상태와 행동열이 같은 결과와 이벤트 로그를 만드는 순수 엔진 테스트
- 모든 베이스 조합, 아웃 수, 타격·안타 결과의 불변식 테스트
- 컴포넌트에서 랜덤 굴리기, 강제 면 입력, 팀명·이닝 재설정 확인
- Playwright에서 홈런 득점, 공수교대, 3이닝 경기 종료까지 실제 조작
- 390px 화면에서 가로 오버플로가 없고 굴리기 버튼이 뷰포트에 고정되는지 확인

## 다음 버전 후보

이번 프로토타입 범위 밖인 전략카드, 비공개 손패, 온라인 동기화는 추가하지 않았다. 다음 단계에서는 카드 타이밍을 엔진 행동으로 먼저 정의하고, 서버가 `transition`을 실행하는 권위형 방 구조를 붙이는 순서가 안전하다.
